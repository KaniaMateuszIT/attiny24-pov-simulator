    Szybki start

    1. Wybierz przykład z listy u góry albo napisz własny program (język: C / C++ jak w PlatformIO albo BASCOM jak w skrypcie do zajęć).
    2. Kliknij Wgraj (F5) – program jest kompilowany prawdziwym kompilatorem avr-gcc 7.3.0 (tym samym, którego używa PlatformIO) i „wgrywany” do symulowanego ATtiny24.
    3. Włącz silnik w panelu po prawej, żeby talerz się kręcił – zobaczysz obraz POV tak, jak widzi go oko.
    4. Zatrzymuj program (F8), wykonuj go krokami (F10 / F11), ustawiaj pułapki (kliknij numer linii) i podglądaj rejestry, zmienne oraz przebiegi na pinach.

    Stanowisko

    PinNrPodłączenie
    PA0…PA713…6anody diod; każda linia ma dwie diody: LED1x w gałęzi Led1 i LED2x w gałęzi Led2 (katody przez 1 kΩ)
    PB02bramka T1 (BS170) – włącza gałąź Led1 (czerwone ramię)
    PB13bramka T2 (BS170) – włącza gałąź Led2 (zielone ramię)
    PB25fotodioda z rezystorem RD 1 kΩ do VCC; stan niski = wykrycie znacznika; to też wejście przerwania INT0

    Dioda świeci, gdy na jej linii PAx jest stan wysoki i tranzystor jej gałęzi przewodzi. Gałęzie leżą na przeciwnych ramionach wirującej płytki, PA0 przy środku. Zegar: wewnętrzny RC 8 MHz (fusebity L:E2 H:D7 E:FF).

    Debugowanie

    • Pułapka (breakpoint) – kliknij numer linii w edytorze. Program zatrzyma się, zanim wykona tę linię.
    • Krok linii (F10) – wykonuje program do następnej linii Twojego kodu; Krok (F11) – jedną instrukcję maszynową (zakładka Asembler).
    • Tempo – zwolnij symulację (1/100, 1/1000), żeby zobaczyć, jak ramię „maluje” obraz kolumna po kolumnie.
    • Rejestry – rejestry procesora i I/O z nazwami bitów. Zmienne i pamięć – wartości zmiennych globalnych, mapa RAM (dane, stos), EEPROM.
    • Analizator – przebiegi czasowe wszystkich pinów i kanał „w przerwaniu”. Przeciągnij myszą, żeby zmierzyć czas.
    • Schemat – kolory przewodów pokazują stan: czerwony = 1, niebieski = 0, pomarańczowy przerywany = pull-up, szary przerywany = pin pływający.

    Typowe pułapki ATtiny24

    • Tylko 2 KB flash i 128 B RAM – duże tablice stałych trzymaj we flashu (const … PROGMEM + pgm_read_byte). Stos rośnie w dół od 0xDF i może wejść na zmienne.
    • Wektory przerwań: INT0_vect, PCINT0_vect, PCINT1_vect, WDT_vect, TIM1_CAPT_vect, TIM1_COMPA_vect, TIM1_COMPB_vect, TIM1_OVF_vect, TIM0_COMPA_vect, TIM0_COMPB_vect, TIM0_OVF_vect. Włączone przerwanie bez ISR = restart programu.
    • Zmienne zmieniane w przerwaniu muszą być volatile; zmienne wielobajtowe czytaj z wyłączonymi przerwaniami (cli() … sei()).
    • Numery pinów Arduino w rdzeniu ATtiny są „odwrócone” (pin 0 = PB0, pin 3 = PA7, pin 10 = PA0) – dlatego na zajęciach używa się rejestrów DDRx, PORTx, PINx.
    • Pin ustawiony jako wejście z PORTx = 1 ma włączony pull-up – dioda na nim świeci bardzo słabo.
    • W przerwaniu nie działa delay() ani millis() (przerwania są wtedy wyłączone).
    • Zapis jedynki do PINx przełącza bit w PORTx (PINA = _BV(PA0) zmienia stan PA0).

    BASCOM-AVR w symulatorze

    Program w BASIC-u jest tłumaczony na C (zakładka „Kod C z BASIC-a”) i kompilowany avr-gcc. Obsługiwany jest podzbiór języka:

    Enable / Disable (… Interrupts), Start / Stop Timer0|Timer1|Watchdog, Reset Watchdog

    If … Then … Elseif … Else … End If (także w jednej linii)
    Do … Loop [Until|While], While … Wend, For … To … [Step] … Next, Exit For|Do|While|Sub
    Select Case z Case 1, 2, Case 3 To 5, Case Is > 7, Case Else
    Gosub / Return, Goto, Sub / Function (Byval, Byref), Call, Local

    Jak dokładny jest symulator?

    Emulator wykonuje kod maszynowy z pliku .hex instrukcja po instrukcji, z dokładnością do cyklu zegara (rdzeń AVR bez mnożenia sprzętowego, jak w ATtiny24). Odwzorowane są porty z pull-upami, Timer0 i Timer1 we wszystkich trybach (z PWM i rejestrem TEMP), INT0, PCINT, watchdog, EEPROM, uśpienie, preskaler zegara i fusebity. Kompilator i biblioteka Arduino są te same co w PlatformIO, więc rozmiary programów i ich zachowanie zgadzają się z płytką. Uproszczone są: ADC, komparator analogowy i USI (nieużywane na stanowisku).

    Quick start

    1. Pick an example from the list at the top or write your own program (language: C / C++ as in PlatformIO, or BASCOM as in the lab handout).
    2. Click Upload (F5) – the program is compiled with the real avr-gcc 7.3.0 compiler (the one PlatformIO uses) and “flashed” into the simulated ATtiny24.
    3. Turn on the motor in the right-hand panel to spin the board – you will see the POV image the way the eye sees it.
    4. Pause the program (F8), step through it (F10 / F11), set breakpoints (click a line number) and watch registers, variables and pin waveforms.

    The lab board

    PinNo.Connection
    PA0…PA713…6LED anodes; each line drives two LEDs: LED1x in branch Led1 and LED2x in branch Led2 (cathodes through 1 kΩ)
    PB02gate of T1 (BS170) – turns on branch Led1 (red arm)
    PB13gate of T2 (BS170) – turns on branch Led2 (green arm)
    PB25photodiode with a 1 kΩ pull-up (RD) to VCC; logic low = marker detected; also the INT0 interrupt input
    PB34RESET (1 kΩ to VCC, push button to ground)

    An LED lights up when its PAx line is high and the transistor of its branch conducts. The branches sit on opposite arms of the spinning board, with PA0 near the centre. Clock: internal 8 MHz RC oscillator (fuses L:E2 H:D7 E:FF).

    Debugging

    • Breakpoint – click a line number in the editor. The program stops before executing that line.
    • Step line (F10) – runs to the next line of your code; Step (F11) – one machine instruction (Assembly tab).
    • Speed – slow the simulation down (1/100, 1/1000) to see the arm “paint” the image column by column.
    • Registers – CPU and I/O registers with named bits. Variables & memory – global variable values, RAM map (data, stack), EEPROM.
    • Analyzer – timing diagrams of all pins plus an “in interrupt” channel. Drag with the mouse to measure time.
    • CPU usage – how much time goes to the main program, interrupts, delay() busy-waiting and sleep, per function and per line.
    • Schematic – wire colours show the state: red = 1, blue = 0, dashed orange = pull-up, dashed grey = floating pin.

    Common ATtiny24 pitfalls

    • Only 2 KB of flash and 128 B of RAM – keep large constant tables in flash (const … PROGMEM + pgm_read_byte). The stack grows down from 0xDF and can run into your variables.
    • Interrupt vectors: INT0_vect, PCINT0_vect, PCINT1_vect, WDT_vect, TIM1_CAPT_vect, TIM1_COMPA_vect, TIM1_COMPB_vect, TIM1_OVF_vect, TIM0_COMPA_vect, TIM0_COMPB_vect, TIM0_OVF_vect. An enabled interrupt without an ISR = program restart.
    • Variables changed in an interrupt must be volatile; read multi-byte variables with interrupts disabled (cli() … sei()).
    • Arduino pin numbers in the ATtiny core are “reversed” (pin 0 = PB0, pin 3 = PA7, pin 10 = PA0) – that is why the lab uses the DDRx, PORTx, PINx registers.
    • A pin set as an input with PORTx = 1 has its pull-up on – an LED on it glows very dimly.
    • delay() and millis() do not work inside an interrupt (interrupts are disabled there).
    • Writing a one to PINx toggles the bit in PORTx (PINA = _BV(PA0) flips PA0).

    BASCOM-AVR in the simulator

    A BASIC program is translated to C (the “C code from BASIC” tab) and compiled with avr-gcc. A subset of the language is supported:

    $regfile, $crystal, $hwstack …
    Dim … As Bit|Byte|Integer|Word|Long|Dword|Single, arrays Dim T(10) As Byte (1-based index)
    Const, Alias (e.g. Led Alias Portb.0)
    Config Porta = Output, Config Portb.0 = Output, Config Portb = &B00001011
    Config Timer0|Timer1 = Timer|Pwm|Counter, Prescale = …, Clear Timer = 1, Compare A = …
    Config Int0 = Falling|Rising|Change|Low Level, Config Watchdog = 16…8192, Config Adc
    On Int0|Timer0|Timer1|Compare1a|Compare1b|Compare0a|Pcint0|Pcint1|Capture1|Wdt Label
    Enable / Disable (… Interrupts), Start / Stop Timer0|Timer1|Watchdog, Reset Watchdog

    If … Then … Elseif … Else … End If (also single-line)
    Do … Loop [Until|While], While … Wend, For … To … [Step] … Next, Exit For|Do|While|Sub
    Select Case with Case 1, 2, Case 3 To 5, Case Is > 7, Case Else
    Gosub / Return, Goto, Sub / Function (Byval, Byref), Call, Local
    Waitms, Waitus, Wait, Set, Reset, Toggle, Incr, Decr, Shift, Rotate, Swap, Bitwait, Debounce
    Data + Lookup(i, Label), Restore + Read, Readeeprom / Writeeeprom, Idle, Powerdown
    functions: Low, High, Abs, Rnd, Getadc, Bits, Nbits, Makeint, Max, Min; operators And Or Xor Not Mod
    registers by name: Porta, Pinb.2, Timer1, Compare1a, Tifr1.tov1, …

    Differences from BASCOM: procedure parameters are passed by value by default (write Byref for a reference); there is no String type and no Print (the ATtiny24 has no UART).

    How accurate is the simulator?

    The emulator executes the machine code from the .hex file instruction by instruction, accurate to the clock cycle (an AVR core without a hardware multiplier, like the ATtiny24). It models ports with pull-ups, Timer0 and Timer1 in all modes (with PWM and the TEMP register), INT0, PCINT, the watchdog, EEPROM, sleep, the clock prescaler and fuse bits. The compiler and Arduino library are the same as in PlatformIO, so program sizes and behaviour match the real board. Simplified: ADC, analog comparator and USI (not used on the lab board).
